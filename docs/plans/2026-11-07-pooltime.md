# pooltime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `pooltime`, a public Rust replacement for bro-cli's LLM subscription pool, at full parity (M1) and then with health/alerts/analytics/debugging/MCP follow-ups, in the new repo `github.com/chrisjenx/pooltime`.

**Architecture:** One Rust binary (`pooltime`) that runs a tokio/axum HTTP daemon exposing an Anthropic-compatible
`/v1/messages` + `/v1/models`, a management API, an embedded dashboard, and (later) MCP. Providers (Anthropic, OpenAI/
Codex) implement one `Provider` trait; routing, accounts, Claude Code profile management, storage and UI are
provider-agnostic. State lives in `~/.pooltime/` (TOML config, per-account credential files, one SQLite DB).

**Tech Stack:** Rust stable (edition 2021), tokio, axum 0.7+/hyper 1, reqwest (rustls, stream; default features off),
rusqlite (bundled), serde/serde_json (`preserve_order`, `arbitrary_precision`), toml, clap 4 (derive), tracing +
tracing-subscriber + tracing-appender, tempfile, fs2 (flock), sha2, base64, rand, url, time, thiserror, anyhow,
rust-embed (dashboard assets), wiremock (tests), assert_cmd + predicates (CLI tests), insta (snapshots), rmcp
(MCP, phase F).

**Spec:** `docs/specs/2026-11-07-pooltime-design.md` (+ `docs/specs/2026-11-07-pooltime-parity-inventory.md`). Session context: `docs/session-2026-11-07.md`.
Executors read both. **Spec §16 overrides earlier spec sections.** Inventory section refs are written `INV §n`.

## Global Constraints

- Repo `github.com/chrisjenx/pooltime`, public. Never open PRs against `JustSuperHuman/bro-cli`; bro-fork PRs (Task 40) use `--repo chrisjenx/bro-cli`.
- Platforms: macOS arm64/x86_64, Linux x86_64/arm64 (musl release builds). No Windows code paths.
- Binary/command name `pooltime`. Data dir `~/.pooltime` (override `POOLTIME_HOME`), mode 0700; creds/DB/config 0600.
- Env overrides prefixed `POOLTIME_` (e.g. `POOLTIME_PORT`, `POOLTIME_HOST`). Generic `PORT`/`HOST` are ignored.
- Default bind `127.0.0.1:3460` (bro uses 3456; both must run side by side during the shadow run).
- Internal utilization unit is a **0–1 fraction**; every parser normalizes.
- Never log or persist prompt/response bodies, tokens, or upstream error messages (only error type + classified reason + upstream `request-id`), except in time-boxed debug mode (redacted headers only).
- Anthropic SSE bytes are forwarded **unchanged** after commit; request bytes are forwarded unchanged unless Codex-thinking stripping removed something.
- Client disconnect never records an account error and never panics/crashes the daemon.
- Every persisted file is written atomically (temp + fsync + rename, parent dir fsync).
- Claude Code profile file rule: `~/.claude` ↔ `~/.claude.json`; other dir `D` ↔ `D/.claude.json`.
- MIT license. Rust tests via `cargo test`; no network in tests (wiremock / in-process fake upstreams only).
- Commit after every task (conventional commits); end commit messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` green before each commit.

## Review Focus

1. **Client cancels mid-stream (Esc in Claude Code) under load** → reservation released, journal says `client_cancelled`, account untouched, daemon keeps serving. Test: Task 19 `client_disconnect_mid_stream_releases_and_records_nothing` (real TCP socket, not an in-memory body).
2. **Silent upstream for minutes (Codex/Anthropic hold)** → Codex path keeps emitting pings every 1 s; Anthropic path emits nothing extra but the idle watchdog fires at the configured limit and the attempt is classified `transport:idle_timeout`. Tests: Task 38 `keepalive_pings_while_upstream_silent`, Task 13 `idle_watchdog_fires_and_empty_chunks_do_not_rearm`.
3. **Claude Code rewrites `.claude.json`/`settings.json` while pooltime patches it** → pooltime retries and never loses Claude Code's concurrent write. Test: Task 4 and Task 26 `guarded_write_retries_when_file_changes_between_read_and_rename`.
4. **Imported account whose stored `refreshTokenExpiresAt` is in the past but the token still refreshes** → stays `ready` (clock alone never sidelines). Test: Task 15 `past_expiry_clock_without_invalid_grant_keeps_account_ready`.
5. **Header-less 429 from Anthropic (request missing Claude Code system prompt)** → passed through to client with `x-pool-upstream-rejected: 1`, no account benched, no failover, no cross-provider hop. Test: Task 18 `headerless_429_is_terminal_passthrough_without_bench`, Task 22 `upstream_rejected_never_hops_provider`.

Rules (INV §2–§3): status precedence `NeedsLogin` (no/corrupt creds or dead fp) > `Billing` > `AccessDenied` > `RateLimited` (explicit until, or spent account-wide window with future reset) > `Ready`. Model-scoped spent windows never change status (exposed via `fn spent_families(&self,id,now)->Vec<String>`). `replace_poll_snapshot` keeps non-duration windows (e.g. `overage`); a poll that started before a billing block must not clear it; spent binding window extends `rate_limited_until`; nothing blocking clears stale cooldown.
