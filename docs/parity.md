# Parity with bro-cli

Every item of the parity inventory (`docs/specs/2026-11-07-pooltime-parity-inventory.md`, cited
as INV) maps to one row of the [checklist](#checklist) below. The [decisions](#decisions) come
first: they are the deliberate differences the checklist refers to.

## Decisions

- **Codex 5xx is terminal within the Codex pool, after a same-account backoff** (INV §4 "Other
  non-OK ... Codex 5xx is terminal within Codex pool today — decide"). Aligned with Anthropic: a
  Codex 5xx is retried on the same account with the overload backoff (`timeouts.overload_retry_*`,
  full jitter, `retry-after` wins) and, if it never clears, surfaced as `Terminal(Overloaded)` with
  a legible `api_error` message; no other Codex account is tried, and the account is not
  sidelined. The cross-provider hop rule still applies (a 500/503/529 is hop-eligible).
  Tests: `server_error_backs_off_then_terminal`, `pre_commit_error_not_streamed_in_200`.
- **Codex pre-commit holds `message_start`** (changed vs bro): the stream commits on the first
  content frame (or the 64 KiB cap / a forced `message_start`), not on `message_start`, so an
  upstream failure right after `response.created` is settled as `Retry`/`Terminal` instead of a
  200 carrying only `message_start` + `error`. Test: `pre_commit_error_not_streamed_in_200`.
- **Codex error types are mapped to the Anthropic set** (changed vs bro, which forwarded Codex
  codes such as `rate_limit_exceeded` as the error `type`). Test:
  `error_frames_use_anthropic_error_types`.
- **Codex 64 KiB pre-commit cap counts upstream bytes as they arrive** (changed vs bro, whose
  check runs only after each whole Bun read). A `response.created` larger than the cap always
  forces `message_start`, and the late real `response.created` becomes an in-place `ping` (the
  same translator rule as bro's). bro may get the whole event in one read, parse it before
  checking the cap, and send neither. The only client-visible difference is that one extra `ping`.
  Test: `oversized_response_created_forces_message_start`; harness scenario
  `codex_oversized_created_single_read`.
- **Rate-limit wording on a non-429 is a quota signal** (ported, an INV §1 omission; ledger
  Ruling T18). bro's `isRateLimit(type, message)` runs before the 5xx/403 arms, so a 403/5xx
  whose error says it is a rate limit benches and fails over like a quota 429. Test:
  `rate_limit_wording_on_non_429_is_quota`.
- **bro's `/models` alias is dropped** (ledger Ruling T23): only OpenAI-style clients used it, via
  the dropped `/v1/chat/completions` (INV §9). Unknown paths get an Anthropic-shaped 404 that is
  logged (`unknown_path_anthropic_404_logged`).

## Checklist

One row per INV item: every `- ` bullet, every row of the §1 response-classification table,
every `**Name**:` paragraph, and every numbered §10 gap. The key is the INV section plus the first
four words of the item (markdown stripped). `harness/src/parity.rs` (run by `cargo test`) fails
when an INV item has no row, a row has no INV item, a status is not one of the five below, or a
cited pooltime test does not exist.

Status: **ported** (same behavior), **changed** (deliberately different; the reason cites the INV
item itself, the spec, the plan or a ledger ruling), **dropped** (not in pooltime; reason given),
**fixed** (an INV §10 bro gap, closed), **partial** (an INV §10 gap only partly closed; what is
open is named).

pooltime tests are Rust test functions (`harness:<name>` = a differential-harness scenario that
compares the behavior against bro). bro tests are `file`: "test title" from bro-cli's suites
(`pool/src/**/*.test.ts`, `src/*.test.js`); "—" means no bro test covers the item.
