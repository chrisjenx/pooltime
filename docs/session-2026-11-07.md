## The ask (user's words, paraphrased)

Pull bro into its own brand-new LLM pooling repo under `chrisjenx`, rewritten from scratch in Rust: faster, lighter,
easier to use; improve as we port; validate against the old functionality so nothing regresses. Super-easy docs and
LLM-friendly setup docs. Fix (if possible) the need to run `accounts login` every few weeks. Good logging and
analytics to debug connection issues. Management from web and MCP so humans and LLMs can manage the pool.

## What the user told us

- Biggest pains: re-running `accounts login`; not noticing an account dropped; account states unclear in the UI;
  suspicion that errors are swallowed.
- Account login itself is fine. The pool should start on startup (user's choice).
- The only thing they check routinely is **7-day usage left**, to decide whether to add or cancel subscriptions —
  pricing/workload changes mean anywhere from ~2 to ~10 subs' worth per week.
- Workflow: `bro start`, then run `claude` agents separately. **No launcher wanted.**
- Alerts wanted: dashboard (A), Claude Code status line (B), macOS notification (C). Not terminal/MCP push, not webhooks.
- Re-login: per-account browser profiles are too aggressive. Use `login_hint`. "Annoying Claude doesn't allow account
  switching like OpenAI does."
- Long-lived (`setup-token`) tokens: not now — must first prove they can read usage and that it's allowed under ToS.
- Carry over Codex/ChatGPT; design for future providers (Grok etc.). An older bro Grok design is kept for reference
  in `docs/specs/reference-bro-grok-routing-design.md`.
- MCP use cases: check pool usage, see which accounts need re-login, tweak weighting (e.g. burn an account sooner).
- Debugging: "add what else you think would be needed". Don't keep data forever — bounded disk.
- Name: **pooltime**. Public; others must be able to install it. macOS + Linux; Windows not wanted.
- Profiles: connect `~/.claude-personal` and `~/.claude` (default); leave `~/.claude-work` off.
- Cutover: full working pool at parity **including settings management and the UI** before switching off bro;
  improvements come in follow-ups.
- Distribution: `curl | sh` and/or Homebrew. User has an Apple Developer ID but doesn't want Apple publishing/signing.
- Wants a full spec + plan and a `/goal` to build everything in the new repo until complete.

## Key findings from investigation (evidence-backed)

### Why accounts need re-login
Anthropic issues each Claude OAuth refresh token with a hard ~27–30-day lifetime from sign-in, recorded by Claude Code
as `claudeAiOauth.refreshTokenExpiresAt` in `.credentials.json`. Refreshing does not extend it — Claude Code stores
`min(old, new)` on refresh and warns "Renewing it does not move that date". bro never reads that field. Accounts
signed in on different days expire one by one, hence "every few weeks". Both dead accounts refreshed normally right up
to their expiry. Not engineerable away with normal logins → make it visible, warn early, batch re-logins.

### Claude Code OAuth facts (from Claude Code 2.1.319 binary strings)
- Authorize URL builder appends `code=true`, `client_id`, `response_type=code`, `redirect_uri`
  (`http://localhost:<port>/callback` or manual `https://platform.claude.com/oauth/code/callback`), `scope`,
  `code_challenge` (S256), `state`, and optionally `orgUUID`, `login_hint`, `login_method`.
- Hosts: `https://claude.com/cai/oauth/authorize` (claude.ai) and `https://platform.claude.com/oauth/authorize`
  (console). Token URL `https://platform.claude.com/v1/oauth/token`.
- `setup-token`: long-lived token, TTL 31,536,000 s (1 year), scope `user:inference` only (parked).
- Distinct refresh failure classes include `oauth_refresh_invalid_grant` and `oauth_refresh_account_on_hold`.
- To be confirmed by spike S1: exact host used for subscription login, and whether `login_hint` works while signed in
  as a different user.

### Observability gaps in bro (full list in inventory §10)
- Account state changes are never logged; failover lines omit reasons; ~700 connection errors (ECONNRESET, idle
  timeouts, unattributed TimeoutError) logged without time/account/request.
- "usage refresh failed (see logs)" with nothing logged; `lastError` single field wiped on next success.
- Log at `~/.bro/pool-proxy.log` (3.4 MB, never rotated) contains prompt fragments.
- Dashboard "Sidelined" conflates needs-login / access-denied / spent window; dead accounts look like full headroom;
  management API unauthenticated; no notifications at all.

### Hard-won bro lessons (from bro project memory) the rewrite must respect
- Header-less 429 from Anthropic (request lacking Claude Code's system prompt) is a per-request refusal: pass through,
  never bench or fail over. A bare-curl 429 is not a pool bug.
- Never error a response stream after the client is gone (killed bro's daemon under Bun).
- Codex: `response.created` can exceed buffers (echoes instructions); keep-alives must be timer-driven, not pulled by
  the consumer; verify streaming with real curl.
- Upstreams sometimes hold silently for minutes under concurrency; prove with `lsof -a` + `nettop`, not guesses.
- Usage endpoint `GET /api/oauth/usage` needs the claude-code UA + `anthropic-beta: oauth-2025-04-20`; body
  utilization is 0–100.
- Model picker: no invented picker text; one row per model; no hard-coded pins behind the gateway (derive from the live
  catalog); a Fable pin would *add* a row; the cached Fable row in `.claude.json` refreshes only with a usable login.
- Codex catalog endpoint `GET chatgpt.com/backend-api/codex/models` lists live slugs/efforts/retirements.
- GPT-5.6's 1M total budget ↔ 872K Codex input/history ceiling.

## Reviews
- **Builder check** (fresh subagent): raised cutover scope, macOS notification packaging, headless Linux → resolved
  (M1 = parity incl. settings + UI; `terminal-notifier` if present else `osascript`; paste-code fallback).
- **Fable review (medium effort)**: ~12 correctness fixes folded into spec §16 — `.claude.json` path rule, race-safe
  writes to Claude Code files, canonical 0–1 utilization, confirm death by probe refresh not clock, identity baseline
  via `/api/oauth/profile` (match on account uuid), minimal M1 status enum, connect requires healthy pool not an
  installed service, disjoint accounts for the shadow run, sign-in inside the daemon, byte-exact request passthrough,
  no upstream error messages in logs, dashboard cookie auth + DNS-rebinding guard, launchd `ExitTimeOut=600`.
  Its suggested scope cuts were declined where they conflicted with the user's decisions; its sequencing (spikes
  first, M1a/M1b/M1c) was adopted.
